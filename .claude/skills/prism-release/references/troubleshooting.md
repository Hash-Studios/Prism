# Prism release: known error modes

| Symptom | Cause | Fix |
|---|---|---|
| `make build-aab` / `make build-ipa` / `make run` fails at `doppler_check failed: missing key in Doppler config: RC_API_KEY` (or `RC_ANDROID_API_KEY`, `RC_IOS_API_KEY`) with `DOPPLER_CONFIG=prd` | Confirmed today: Doppler `prd` only has `REVENUECAT_ENTITLEMENT_ID`, `REVENUECAT_IOS_API_KEY`, `REVENUECAT_USE_IN_MEMORY`. `lib/env/env.dart` reads `RC_API_KEY`, `RC_ANDROID_API_KEY`, `RC_IOS_API_KEY`. `dev` has the three `RC_*` names `prd` lacks | Stop and tell the human. Do not add the keys to Doppler yourself and do not fall back to `dev` for a release build. A `dev`-backed release build ships dev Firebase/RevenueCat config to real users |
| `firebase deploy` / `firebase functions:secrets:set` fails or targets the wrong project | The logged-in Firebase CLI account cannot see `prism-wallpapers`. Confirmed today: `firebase projects:list` returned only unrelated projects for the default account | `firebase login:add` to add an account with access, then `firebase login:use <email>`. Re-run `firebase projects:list` to confirm `prism-wallpapers` now appears before deploying |
| `flutter build appbundle` (via `make build-aab`) fails with `Keystore file not found` or `Failed to read key 'upload'` (or whatever alias `android/key.properties` names) | `android/key.properties` or the keystore path it points to is missing or wrong. Both are `.gitignore`d; confirmed absent in a fresh worktree checkout | Have the human decrypt `android/android_keys.zip.gpg` via `.github/scripts/decrypt_android_secrets.sh` (needs `ANDROID_KEYS_SECRET_PASSPHRASE`, human-only). Do **not** regenerate the keystore. A new upload key breaks Play Store updates for every existing install |
| `bundle exec fastlane beta` fails with a Play API auth error | `android/google-play-console.json` is missing (gitignored, confirmed absent) or the service account lacks release-manager access to `com.hash.prism` | Ask the human to supply the JSON key at that path, or to upload the `.aab` manually in Play Console instead |
| Fastlane lane `beta` uploads to a track you didn't expect | `android/fastlane/Fastfile` has exactly one lane, `beta`, and it always targets Play's `beta` track with `release_status: completed`. There is no `internal` lane in this repo | If `internal` is wanted first, upload manually in Play Console and choose the track there. Don't assume fastlane can do it |
| `asc doctor` / `asc publish testflight` fails auth | `asc` profile misconfigured, the private key file moved, or the key belongs to a different team (then `asc apps list` does not show `com.hash.prism`) | Run `asc auth doctor` for specifics. Re-run `asc auth login` with an API key from the team that owns Prism (`X2955Z4CKQ`) |
| `asc publish testflight` uploads a build number ASC already has, or App Store Connect's next number disagrees with `pubspec.yaml` | This repo has no automated ASC/Play build-number desync guard (`tool/sync_app_version.py --check` only checks `pubspec.yaml` against `lib/core/constants/app_constants.dart`, not against either store) | Before bumping, run `asc builds next-build-number --app 6670200846 --version <VERSION> --platform IOS` and `gplay status --package com.hash.prism`. If either disagrees with the planned number, stop and ask the human which number to use |
| iOS crash reports in Sentry are unsymbolicated after a release | The build came from a checkout older than the 3.0.9 release branch, where `make build-ipa` did not pass `--obfuscate --split-debug-info` or run `tool/sentry_upload.sh` | Build from current `master`. `make build-ipa` now obfuscates and uploads symbols like `make build-aab` |
| `firestore.rules` deploy blocks a wallpaper download / coin spend for some users right after release | Rules were tightened to reject direct client writes to `coins`/`premium` before enough users updated off an old build that still wrote those fields directly | This is exactly the ordering step 6 of the skill warns about. Revert the rules deploy (`firebase deploy --only firestore:rules` with the previous rules checked out) and wait for more client adoption before retrying |
| `npm run migrate:username-lower` (or `migrate:view-stats`) run with `-- --apply` by mistake during what was meant to be a dry run | The npm script name is the same for dry run and apply; only the trailing `-- --apply` flag differs | Re-run without `-- --apply` to confirm dry-run output first next time. If a bad apply already ran, the migration script's own idempotency (it only updates docs where the value differs) limits damage. Re-run the dry run to see what's left un-migrated, then decide next steps with the human |
| `python3 tool/sync_app_version.py --check` fails after a manual edit | `lib/core/constants/app_constants.dart`'s `currentAppVersion` / `currentAppVersionCode` were hand-edited or the pubspec bump wasn't synced | Run `python3 tool/sync_app_version.py` (`make version-sync`), never hand-edit `app_constants.dart` |
| A release build runs with Firebase off (no auth, no Firestore) | `android/app/google-services.json` was missing, so the Makefile added `--dart-define=SKIP_FIREBASE_INIT=true` | Copy the Firebase config files from the main checkout (Preconditions step 3). Current `build-aab` and `build-ipa` stop with an error instead |
