# Prism-specific gotchas

Things that look like the bug but are actually the environment, or things that will silently
undo your fix if you skip them.

## `lib/firebase_options.dart` is gitignored

Line 61 of `.gitignore`. Normally generated by `flutterfire configure`. A fresh worktree does
not have it, and `analyze`/`test`/`build` will fail confusingly (Firebase init errors) without
it. Stub it per `AGENTS.md` and the main SKILL.md. Never commit the stub; check `git status`
before staging if you're unsure it slipped in.

## `functions/lib` is compiled output, but it is tracked in Git

Most repos gitignore build output; Prism does not for `functions/lib`. If you edit
`functions/src/*.ts` and forget to `npm run build`, your PR diff will show only the source
change while the deployed-looking compiled JS in `functions/lib` still reflects the old
behavior, and `functions-ci`'s `node --test lib/__tests__/*.test.js` will run against stale
code. Always rebuild after a functions edit and include the resulting `functions/lib/**` diff.

## A Cloud Functions fix is not live until deployed

Client code and Cloud Functions callables live in the same repo but ship independently. Merging
a PR that fixes `functions/src/coinsCallables.ts` does not change what's running in prod; that
needs `firebase deploy --only functions` (or `npm run deploy`), which is a separate,
authorization-gated action. When reporting a functions fix, say explicitly whether it has been
deployed or only merged, since prod can lag the repo.

## Firestore permission-denied errors carry a `sourceTag`

`lib/core/firestore/firestore_tracked_client.dart` logs the collection and a `sourceTag` string
on every `permission-denied` (queries, transactions, and batches). Grep the `sourceTag` value
back to its call site (`grep -rn "sourceTag: '<tag>'" lib/`) instead of guessing which write
tripped a rule in `firestore.rules`. Confirm whether the rule is too strict or the client is
writing/reading something it shouldn't before choosing which file to change.

## Router changes may need codegen

`lib/core/router/app_router.dart` and `route_guards.dart` are hand-written; `app_router.gr.dart`
is generated by `build_runner` (`make file-gen`). A route/guard edit that isn't followed by
`make file-gen` will compile against a stale generated router and can pass a narrow test while
failing at runtime. `deep_link_parser.dart` and `notification_route_mapper.dart` feed the same
router; check both when a deep link or notification tap routes to the wrong screen.

## Gates run through `fvm`, not bare `flutter`

Local Flutter commands should go through `fvm flutter ...` (or the Makefile, which already does
this) so the pinned version in `.fvmrc` is used. `CI=true` switches the Makefile to bare
`flutter`/`dart` and adds `--no-fatal-infos` to `analyze`: that's what CI itself does, and it's
the fastest way to get a clean local `analyze` exit without installing FVM's pinned SDK.

## Device proof and screenshots are owned elsewhere

Use the `verify-prism` skill for on-device or simulator proof; don't build a parallel screenshot
flow inside a bug fix. PR screenshots go on the `qa/screenshots` orphan branch, referenced from
the PR description, not committed into the product tree.
