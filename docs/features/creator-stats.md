# Creator stats

Open **Stats** on your own profile, on **Your uploads**, or in the creator progress card on **Rewards**. The upload entry is present when the upload list is empty. The review list continues to show pending and rejected uploads only.

The dashboard shows approved walls for the signed-in creator. It calls `getCreatorStats({})` when opened and on retry. A session identity change discards the old page BLoC and pending response before loading the new creator. Signing out clears the stats and shows the sign-in prompt. The server derives ownership from the authenticated UID. The client does not send a creator ID. The signed-in route is `/creator-stats`; the public deep link is `prism://creator-stats`.

The page answers one question first: how are my walls doing this week? A period switch at the top selects **This week**, **Last week**, or **4 weeks**. The hero shows the selected metric for that period, its change against the period of the same length before it, and its total. The change shows the difference and, when the earlier value is above zero, the percentage. This week is compared with last week. Last week is compared with the week before. The four newest weeks are compared with the four weeks before them. When a week in either window is unavailable, the hero says that there is not enough history to compare. Weeks start on Monday at 00:00 UTC. The chart contains exactly eight weeks in oldest-first order. It strongly marks the weeks in the selected period. Below the chart, one tile for each metric shows the period value and its change. Tap a tile to select that metric for the hero, the chart, and the wall order. Changing the metric or the period resets the chart readout to the newest week of the selected period. Top walls are sorted by their value for the selected metric and period, with unavailable values last. Equal values use the wall ID as a stable order. The list shows five walls and a **Show all** button when there are more. Select a wall to view its eight-week history from the same response, with the same period switch, hero, chart, and tiles. Wall detail uses that response snapshot; it does not fetch newer stats. Tips have their own card below the walls. **About these numbers** at the end holds the week, history, and counting notes and the update time.

A dash or a short grey mark means that history is unavailable. Zero means that tracking recorded no activity. The client keeps these values separate. The current week is incomplete. Tracking can begin partway through a week, so a recorded value can cover only part of that week. The chart has a value axis with zero, the middle, and a rounded top, and localized short week dates. A line above the chart shows the exact value and full date of the selected week. The newest week of the selected period is selected first. Tap a bar to read another week. Each bar is a screen-reader button that names its week date and its value or unavailable state. When all eight values are known and zero, a calm note replaces the chart and suggests sharing a wall. If some weeks are unavailable, the chart remains visible so those weeks are not hidden; known zero weeks remain distinct from unavailable weeks. Numbers, percentages, and dates use the active locale. Axis numbers use the locale's compact form. Tiles stack in one column at large text, and the page scrolls. On wide screens the page keeps the readable width and the tiles use three columns. The chart uses theme colours and the user accent, and it has no motion.

Save totals count current favourite membership. Weekly saves count additions. Remix totals count current credited remixes. Weekly remixes count first accepted credits. Folder additions start when tracking starts. The app does not invent old history.

The repository validates the schema version, UTC timezone, eight contiguous Monday week boundaries, non-negative integer counts, and matching wall histories. A callable or parsing failure shows a retry action. An account with no approved walls sees Glint and an upload action.

The weekly inbox message uses copy kind `creatorStatsWeekly` with `{week: string}`. Its route is `creator_stats`. The localized title is **Your walls this week**. It opens the dashboard with analytics source `inbox`. The server owns notification eligibility, scheduling, and stored fallback copy.

Typed events are `creator_stats_opened` with `source`, `creator_stats_metric_switched` with `metric`, and `creator_wall_stats_opened` with `wall_id`. Entry sources are `profile`, `uploads`, `rewards`, `inbox`, and `link`.

## Integration and verification

The app needs the server callable and authenticated demo data before live verification. Deploy rules, indexes, and Functions before the store build. This document does not authorize a deploy.

Focused tests cover nullable counts, invalid histories, period windows, the axis top, BLoC loading, loading and failure UI, empty state at large text, the hero and its comparisons, the period switch, metric tiles, walls with no views, the top walls cap, the whole page at 320 points and 200% text, wall detail, and bar semantics. Goldens in `test/features/creator_stats/goldens/` cover light, dark, AMOLED with a user accent, 200% text, a tablet, and walls with no views. Router, DI, localization, and analytics files are generated with the repository tools. The parent integration owns full `make ci` and device proof.

Android and iOS device proof ran on a Mac against demo Firebase emulators. See `creator-stats-proof.md`. No production data is needed.

Independent review and local validation are recorded in `creator-stats-review.md`. Full gates and device proof are recorded in `creator-stats-proof.md`. No dependency change, merge, or deploy was performed.
